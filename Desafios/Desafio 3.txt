Dia 3 - Parte2: Shell Script

Vamos avançar um pouquinho mais e falar agora de funções.


O projeto BIA é uma aplicação em Node com React.
A parte do React são arquivos estáticos (HTML, JavaScript, CSS).
Imagina que eu quero construir um script Shell que vai gerar, fazer um build dos artefatos da BIA, do React, vai fazer o envio disso para o S3.

Vou construir aqui um arquivo que passe primeiro essa ideia, segue as etapas que envolve esse processo:

script: deploy.sh

Primeira coisa que se precisa fazer:
	- nosso usuário com a AWS CLI (isso já foi feito no desafio anterior)
	- Criar no S3 um bucket (será onde ficará os arquivos), mas precisa fazer uma configuração aqui para que esse bucket consiga funcionar como um host, para hospedar o nosso site.
		- Amazon S3 > Buckets > Create bucket
			- Bucket name: desafios-fundamentais-aws1-bia
		- Eu vou servir uma aplicação estática, então, eu preciso ter acesso público para esse repositório, vamos desmarcar essa opção: Block all public access
		- Clica em: Create bucket
		- Tem um script que a gente precisa colocar no bucket.

	- Agora precisamos Habilitar website host estático.
		- Clica no bucket que foi criado: desafios-fundamentais-aws1-bia
		- Depois clica em: Properties
			- clica para editar essa opção: Static website hosting
				- selecione: Enable
				- Index document: index.html (Assim que eu bater aqui, ele vai carregar qual arquivo? Será o index.html)
				- clica: Save changes

	- Agora precisamos adicionar um bucket policy, ele dá acesso de leitura aos arquivos desse bucket, para quando alguém bater nele venha conseguir ler esses arquivos e a aplicação rodar.
		- Clica em Permissions
		- Clica em editar Bucket policy e cole:
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": [
                "s3:GetObject"
            ],
            "Resource": [
                "arn:aws:s3:::desafios-fundamentais-aws1-bia/*"
            ]
        }
    ]
}

		- clica: Save changes


Tutorial: https://docs.aws.amazon.com/AmazonS3/latest/userguide/HostingWebsiteOnS3Setup.html

Se tudo estiver ok, meu bucket está preparado para receber o meu projeto.

📌 Dinâmica da Arquitetura e do Desafio:
Com base nas instruções e na imagem, aqui está como o seu Shell Script e a AWS vão se comportar dentro desse desenho:

S3 (bia assets): O bucket que você vai criar assumirá o papel de hospedar e servir todo o front-end de forma estática. Note que ele expõe os assets para o ENDPOINT do usuário.

O Script de Automação: Seu script Shell precisará receber a URL da API da BIA como argumento. Isso garantirá que, ao fazer o build, o React saiba exatamente para qual Endpoint (bia-web / bia-dev) enviar as requisições.

Sync com a Nuvem: O comando aws s3 sync no seu script fará a ponte entre os assets gerados localmente/na WSL e a caixa do S3 bia assets.

Isolamento do Banco (X no diagrama): Conectar do WSL para bia no RDS, não vai funcionar, porque ele não publicamente acessível, então ele não tem essa permissão de fazer isso aqui. Então devemos fazer se conectar por SSM no bia-dev, e no bia-dev, rodar a migrate para criar a estrutura relacionada no Bia RDS.
